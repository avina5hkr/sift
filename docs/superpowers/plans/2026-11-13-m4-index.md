# M4: Index and exact duplicates

Working method: `CLAUDE.md`. Roadmap: section 5, M4. Spec: 8 A–B, 10 (tabs, keeper priority,
selection), 11 (Cleanup home, Review screen). Nothing in M4 deletes anything; Delete selected
stays disabled until M8.

## Features, in build order

1. **Indexer** (`analysis/index.py`, stage A, analysis_version 1): for every content with a Mac
   (else SSD) replica: kind, mime, width, height, EXIF orientation applied, `has_camera_exif`
   (EXIF Make or Model), `is_screenshot` (path contains Screenshots or name starts with
   `Screenshot_`, else no camera EXIF and size equals a phone screen size in either orientation),
   `unreadable` on decode errors, a 256 px JPEG thumbnail in the cache folder. Pillow +
   pillow-heif; `Image.MAX_IMAGE_PIXELS` raised. Resumable, runs as the `analyze` task.
2. **Exact duplicates** (`analysis/exact.py`, stage B): present phone paths sharing a content
   hash, per phone.
3. **Candidates** (`cleanup/candidates.py`): rebuild `candidate` rows for tab `exact`: one group
   per hash, keeper by priority DCIM/Camera > Pictures > WhatsApp received > WhatsApp Sent >
   other, ties to the earlier mtime; copies `default_checked = 1`. Selection (`selection`
   table) is kept across rebuilds and never overwritten by defaults.
4. **API**: `POST /api/cleanup/analyze`, `POST /api/cleanup/cancel`, `GET /api/cleanup/summary`
   (storage by category: Camera, WhatsApp images, WhatsApp video, Sent, Other; card counts and
   reclaimable size; staleness), `GET /api/cleanup/candidates?tab=&sort=&cursor=` (groups with
   keeper and copies), `POST /api/selection` (ids + checked, or all_in_tab + checked),
   `GET /api/media/{phone_file_id}/thumb`, `/preview?max=1600`, `/file` (HTTP Range, for video).
   Media security tests: token required (header or query), missing Host, HEAD, traversal.
5. **Web**: Cleanup home (storage bar, Analyze button disabled until a backup exists, Exact
   duplicates card), Review shell (tabs, Exact enabled; group rows with KEEP; grid items with
   checkbox, Shift-click range; sticky footer with Select all / none; lightbox with arrows and
   the side panel; keyboard keys from spec 11; windowed list for 20k items).
6. **Benchmark**: 20k items, first paint and scroll, recorded in `docs/spikes/m4-review.md`.

## Exit

Exact duplicates tab works end to end with previews (fake phone e2e); 20k benchmark recorded;
full suite, lint, web tests, e2e green; one whole-branch review.

## Assumptions

- B1. Videos get kind, size and duration only when the container says so cheaply; their poster
  thumbnails and fingerprints come with M5 (a video placeholder tile until then).
- B2. Phone screen sizes come from the connected phone's `wm size` and are cached per phone in
  the `setting` table (`screen_sizes:<device uuid>`); without them only the path and name rules
  mark screenshots.
- B3. Thumbnails and previews live in the cache folder (`<cache>/thumbs`, `<cache>/previews`),
  keyed by content hash; they are disposable and rebuilt on demand.
- B4. The Analyse phone result keeps counts only; its file lists move to M8 with the delete from
  analysis.
- B5. Only one phone's candidates are shown: the stored phone.

## Outcome (2026-11-13)

Built as planned; benchmark in `docs/spikes/m4-review.md` (first paint 166–315 ms, scroll p95
~17 ms with 20k items). One whole-branch review: no critical, 5 important (stale candidates,
shared temp file for renders, full-size decodes on the preview path, reading a drive not found
by UUID, select-all racing a page load); all fixed with tests. Candidates are now rebuilt after
every backup run. Deferred minors (DCIM subfolders ranked as Camera, WhatsApp documents counted
as images) go to M5's keeper and category work.
