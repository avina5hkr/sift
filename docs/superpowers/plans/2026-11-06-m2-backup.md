# Sift M2 Backup to Mac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sift backs up the ticked backup sets from a connected Android phone to the Mac backup folder. Every copy is verified, interrupted runs resume, the quit path is clean, a mass-disappearance guard is in place, and a first-run wizard sets everything up.

**Architecture:** A `JobManager` runs one backup job at a time on threads. Each job runs scan → plan → pull → verify against the phone through the transport owned by the `DeviceTracker`, which shares one connection-slot pool per phone. Files land as `.staging/UUID.part` and become final only after a complete, hashed, flushed, renamed and re-read copy (invariant I2). Rows go through `Database.tx()`. Progress goes out as SSE events every 500 ms. SSD replication, adoption and verify are M3.

**Tech Stack:** M0/M1 stack, plus Pillow (EXIF date, for the optional `by_date` layout only) and `pyobjc-framework-UserNotifications` (end-of-run notification). `PyObjCTools.MachSignals` for window-mode signals.

**Spec:** the maintainer's private product spec. It is kept out of this repository. Section numbers refer to it, and every requirement a task needs is restated in the task itself. Roadmap: `docs/superpowers/plans/2026-11-05-sift-roadmap.md` (M2 entry; sections 7 and 8 carry-over). Measurements: `docs/spikes/pre-m2-inputs.md`, `docs/spikes/m1-device.md`.

## Global Constraints

- **Invariants:**
  - **I1:** backup never deletes or overwrites a file already in a backup destination.
  - **I2:** a replica row exists only after the file was written under a temporary name, flushed (`fcntl F_FULLFSYNC`), renamed, and read back (`F_NOCACHE`) with a matching SHA-256.
  - **I5:** every job is idempotent and resumable. Killing the app at any moment leaves no partial file under a final name, and no row claims more than the disk holds.
  - **I7:** nothing writes to the phone in M2.
- **Never write to the phone.** `delete`, `push` and `media_rescan` stay unimplemented on `AdbTransport`.
- **adb server:** attach to the shared one on 5037. Start one only when the port refuses connections. Never kill or restart a server. From Task 4, every adb connection uses Sift's own raw-socket code (`sift.device.adbwire`). adbutils is removed.
- **Scan rules:**
  - Rows not seen in a scan get `present = 0`. They are never deleted.
  - A file is new or changed only if it has no row, or its size or mtime differs.
  - **Settle rule:** skip a file whose mtime is within 120 s of the phone's clock, or whose size changed between two stats 2 s apart.
  - **Space check:** the bytes needed, plus 2%, must be free on each destination.
- **Pull:**
  - 1 MiB chunks, hashing while reading.
  - Order: camera files newest first, then WhatsApp, then everything else.
  - Retries after 2 s, 5 s and 15 s, then `failed`. After 20 failures in a row the job pauses.
  - A disconnected phone **pauses** the job ("Waiting for phone") and never fails it.
- **Layout:**
  - **`mirror` (default):** `ROOT/DEVICE_LABEL/<phone path without /sdcard/>`.
  - **`by_date` (Camera, Pictures and Movies only):** `ROOT/DEVICE_LABEL/Camera/YYYY/YYYY-MM/NAME`, dated by EXIF DateTimeOriginal, else mtime.
  - **Name rules** for every path component:
    - replace ``< > : " \ | ? *`` and control characters with `_`;
    - strip trailing dots and spaces;
    - normalise to NFC;
    - at most 255 UTF-8 bytes: shorten the stem, keep the extension, and add `_HASH8`;
    - Windows reserved names get a trailing `_`.
  - **Collisions:** compare `rel_key` (NFC plus casefold). Different content gets `_HASH8` before the extension.
  - The chosen `rel_path` is stored once and never recomputed.
- **Progress over SSE every 500 ms:**
  - stage and state (idle, scanning, pulling, paused, waiting_for_phone, done, failed);
  - files and bytes, total and done;
  - duplicates skipped and failed counts;
  - the 3 current files;
  - speed as a 5 s moving average, and the ETA.
  - Pause and Stop finish the current file first.
- **Reference speed** before any measurement: 37.5 MB/s over USB 2. Never assume USB 3. `parallel_reads_usb` comes from the first-run reader test (1, 2 and 4 readers for 3 s each).
- **Text and tokens:** plain-words UI text, with no stack traces or errno strings. The token rules from M0 stand.
- **Public, vendor-neutral repository:**
  - No personal data, serials, model names, user paths, or the spec.
  - Test fixtures are synthetic.
  - Real-phone output is recorded as totals only.
- **Tests never touch real things:**
  - Tests never contact the real adb server (`SIFT_TRACKER=off`) or the owner's real folders.
  - Manual real-phone runs write only under `build/`, never into the owner's existing backup folders.
- **Commits:** the owner's identity through the repo-local config, with no AI trailers. Never push. mypy strict for `sift.core`, `sift.device`, `sift.backup` and `sift.services`.

## Review Focus

1. **A read that ends early, or a crash mid-file.**
   - Expected: no file under a final name, the `.part` removed or swept at startup, and the row back to `discovered`.
   - Tests: Task 2 `test_short_stream_never_produces_final_file`; Task 13 P1 and P2.
2. **A folder that suddenly looks empty.** For example, an unreadable folder that looks empty (M1 ruling R14), or a card reader that is unmounted.
   - Expected: no rows flip to `present = 0` and nothing changes until the owner confirms.
   - Test: Task 10 `test_mass_disappearance_stops_until_confirmed`.
3. **Several devices attached, or an emulator running.**
   - Expected: the wizard asks which phone. Backups only run against the stored phone, and a different phone never receives or provides data.
   - Tests: Task 16 `test_device_picker_*`; Task 11 `test_job_refuses_wrong_device`.
4. **Quitting mid-backup through every route:** Cmd-Q, close, Ctrl-C, SIGTERM.
   - Expected: stop at a file boundary, the DB closed cleanly, and the lock freed.
   - Tests: Task 1 subprocess tests plus the manual window check.
5. **Odd real names.** A folder that starts with a space, names ending with a dot (hundreds in WhatsApp `Documents/Sent`), non-UTF-8 names, and case-only collisions.
   - Expected: every file is stored, with no overwrite, under a deterministic name.
   - Tests: Task 9 layout tests; Task 13 property tests over hostile names.

class Shutdown:
    def __init__(self) -> None: ...
    def add(self, name: str, step: Callable[[], None], *, timeout_s: float) -> None: ...  # run in reverse order of adding
    def request(self, reason: str) -> None: ...      # idempotent; safe from any thread or signal handler

- `JobManager.stop_all(timeout_s)` arrives in Task 11. Until then the jobs step is a no-op that the tests stub.

### Task 2: A short or failed read can never become a final file

**Files:**
- Create: `src/sift/backup/__init__.py`, `src/sift/backup/staging.py`, `tests/backup/test_staging.py`.
- Modify: `src/sift/device/adb_transport.py` (stream fixes), `tests/device/test_adb_transport_unit.py`.

**Interfaces — produces:**
```python
class StagedFile:                     # context manager; the only way bytes reach a backup folder
    def __init__(self, staging_dir: Path, *, expected_size: int) -> None: ...   # creates .staging/<uuid4>.part (O_EXCL)
    def write(self, chunk: bytes) -> None: ...      # updates sha256 and byte count
    @property
    def sha256(self) -> str: ...
    def commit(self, final_path: Path, *, mtime: int) -> str: ...
    # Requires bytes == expected_size and the stream ended cleanly.
    # F_FULLFSYNC, then rename into place without replacing an existing file
    # (link + unlink, or renamex_np RENAME_EXCL), then utime.
    # Re-reads with F_NOCACHE and returns the verified hash.
    # Raises IncompleteCopy / ChecksumMismatch / TargetExists; on any of these
    # the final path does not exist afterwards.
    def __exit__(self, *exc: object) -> None: ...   # removes the .part unless committed
class IncompleteCopy(Exception): ...; class ChecksumMismatch(Exception): ...; class TargetExists(Exception): ...
def sweep_staging(staging_dir: Path) -> int: ...    # deletes stale *.part at startup; returns the count
```

**Working on exFAT** (the SSD in M3) as well as APFS:
- **Rename without replacing:** first try `renamex_np(src, dst, RENAME_EXCL)` through ctypes (libc). If it fails with `ENOTSUP` or `EINVAL`, fall back: take a process-wide `threading.Lock`, check that the target does not exist (`os.lstat` raises `FileNotFoundError`), then `os.rename`. `EEXIST` from either route becomes `TargetExists`. Sift is the only writer to its backup folder, and `instance.py` already makes it one process, so the lock covers the fallback.
- **Flush:** `fcntl(fd, F_FULLFSYNC)`. If that raises `OSError` with `ENOTSUP`, `EINVAL` or `ENOTTY`, fall back to `os.fsync`, and log one warning per destination (a module-level set of warned devices, keyed by `st_dev`).

**More tests** (the failures are simulated by monkeypatching):
- `test_commit_falls_back_when_renamex_unsupported`: `renamex_np` gives ENOTSUP, `os.rename` is used, and the file lands.
- `test_fallback_rename_refuses_existing_target`: on the fallback path, an existing target raises `TargetExists` and leaves it untouched.
- `test_commit_falls_back_to_fsync_and_warns_once`: `F_FULLFSYNC` gives ENOTSUP. `os.fsync` is called on both commits, but only one warning is logged.
- `test_renamex_einval_falls_back`.

**Stream fixes (M1 carry-over, "must"):**
- `StallGuardedStream._next_chunk` wraps the short-end hook, so any exception falls back to the plain short end. A failure is stored before `_ended`, so later reads raise again and never return `b""`.
- A failed stream stores a traceback-free copy of its error (no reference cycle).
- A concurrent double `close()` releases the slot exactly once.

**Tests:**
- `test_short_stream_never_produces_final_file`: a fake stream ends 1 byte early, then `commit` raises IncompleteCopy, the final path is absent and no `.part` remains.
- `test_exception_mid_write_leaves_no_final_file`.
- `test_commit_never_overwrites_existing_final`: I1.
- `test_reread_mismatch_removes_final_and_raises`: the read-back is corrupted by monkeypatching.
- `test_full_fsync_called`: `fcntl.fcntl` is spied with `F_FULLFSYNC`.
- `test_sweep_staging_removes_only_parts`.
- In AdbTransport:
  - `test_short_end_hook_failure_still_raises_on_every_read`
  - `test_failed_stream_has_no_reference_cycle` (`gc` with `gc.disable()`)
  - `test_concurrent_close_releases_once`

### Task 10: Scanner with settle rule, warnings and mass-disappearance guard

**Files:** create `src/sift/backup/scanner.py`, `tests/backup/test_scanner.py`.

**Interfaces:**
```python
@dataclass(frozen=True)
class ScanResult:
    scan_id: int; state: Literal["applied", "awaiting_confirmation"]
    new_or_changed: int; bytes_needed: int; unchanged: int; settling: int; skipped_by_rule: int
    warnings: tuple[str, ...]           # plain words, e.g. "Could not read /sdcard/X; skipped."
    disappearance: tuple[Disappearance, ...]
@dataclass(frozen=True)
class Disappearance: scope: Literal["folder", "set"]; name: str; before: int; now: int
def scan(session: DeviceSession, db: Database, roots: Sequence[ScanRoot], rules: SkipRules,
         *, clock: Clock, settle_s: int = 120, recheck_s: float = 2.0, sleep=time.sleep) -> ScanResult: ...
def confirm_scan(db: Database, scan_id: int) -> None: ...   # owner confirmed → apply staged result
def discard_scan(db: Database, scan_id: int) -> None: ...
def space_check(bytes_needed: int, dest: Path, headroom_pct: float) -> str | None: ...  # plain shortfall message or None
```

**Decisions:**
- **Traversal:** walk each root with `on_error`. An unreadable folder or entry adds a warning and is skipped. **Rows under a skipped folder keep their previous `present` value**, because their state is unknown. Shallow roots use `list_dir` and take files only.
- **Staging the result:** the result goes into `scan_entry` first. Nothing in `phone_file` changes during the walk.
- **Settle rule:**
  - Skip, and count as settling, files whose mtime ≥ `phone_time − 120`.
  - New or changed candidates with an mtime within the last hour are stat'ed again after one shared 2 s wait, and skipped if their size changed.
  - Older files are not double-stat'ed, since an in-flight write has a recent mtime. This keeps a 60k-file first scan cheap.
- **Mass-disappearance guard**, evaluated before applying, comparing the staged result with `folder_count` and the present rows per set:
  - **(a)** any folder, or any set, that had at least 1 present file in the last applied scan and now has 0;
  - **(b)** any set losing more than 20% of its present files.
  - Either one sets `state = awaiting_confirmation` with plain warnings, such as "WhatsApp media had 33,000 files last time and now shows 0. Nothing was changed. If you deleted them on purpose, confirm; otherwise check the phone and scan again.", and returns **without touching `phone_file`**.
  - `confirm_scan` applies it, and `discard_scan` drops it.
  - The guard does not apply to the first scan of a set, since there is no history.
- **Applying** happens in one `Database.tx()`:
  - upsert rows (path, size, mtime, origin, set_name);
  - set `present = 1` for seen rows;
  - set `present = 0` only for unseen rows of scanned, non-skipped folders;
  - update `folder_count`.
- **New or changed:** no row, or a size or mtime difference.
- **Space check:** the bytes needed for the Mac destination, plus 2% headroom, and the destination must be writable.

**Tests:**
- `test_unchanged_files_are_not_read`: a transport spy records zero `open_read` calls.
- `test_settle_rule_skips_recent_and_growing_files`, using ManualClock and a fake that grows a file between stats.
- `test_unreadable_folder_is_skipped_with_warning_and_rows_kept`.
- `test_mass_disappearance_stops_until_confirmed`:
  - **Folder empties:** a folder goes from 50 present files to 0. Expect `awaiting_confirmation`, `phone_file` unchanged, and `confirm_scan` then flips them.
  - **Set drops:** a set drops 25%. Expect the guard. A drop of 15% passes.
  - **R14 case:** an unreadable folder that lists empty triggers the guard.
- `test_first_scan_has_no_guard`.
- `test_shallow_root_lists_only_direct_files`.
- `test_rows_never_deleted`.
- `test_space_check_names_the_shortfall`.

### Task 12: Puller and recovery

**Files:** create `src/sift/backup/puller.py`, `src/sift/backup/recovery.py`, `src/sift/backup/readers.py` (first-run reader test), plus tests.

**Decisions:**
- **Order and readers:**
  - Pull order: camera newest first, then WhatsApp, then the rest.
  - `parallel_reads_usb` readers, each with its own stream. The total stays within the shared slot pool.
- **Copying one file** (I2):
  1. Stream through `StagedFile`.
  2. On a byte-count mismatch: `stat` again. If the file changed, set the row back to `discovered`; otherwise it's a failed attempt.
  3. **Dedupe:** if the content hash already has a Mac replica, drop the `.part` and alias the phone_file to it (`duplicates_skipped += 1`).
  4. Otherwise choose `rel_path` once (layout and collision), commit, verify the read-back, then insert the content and replica rows **in one tx after** the commit. The crash point `puller.after_rename_before_rows` sits between the commit and that transaction.
  5. **`TargetExists`** on commit (for example, a crash at that crash point left a file without rows):
     - Hash the existing file (`F_NOCACHE` read). If its SHA-256 equals the pulled hash, delete the `.part`, keep the existing file, and insert the content and replica rows for it. No `_HASH8` copy.
     - If the hash differs, choose the `_HASH8` path through `resolve_collision` and commit there. That target existing too is an error, and the file is marked `failed` with a plain reason.
     - Either way, the existing file is never modified (I1).
- **Fast path for moved files:** a new path with the same size and mtime as known content → phone `sha256` → link without transfer.
- **Row states:** `discovered → pulling → done | failed | discovered`.
- **`FileChanged`** → back to `discovered` (retried next run) with a warning.
- **Recovery at startup:**
  - `sweep_staging`, and reset `pulling → discovered`.
  - `reconcile()`: every Mac replica row must have a file of the right size, otherwise delete the row so the next run copies it again. Destinations that aren't mounted are skipped.
- **First-run reader test:** 1, 2 and 4 readers for 3 s each on the largest files. **The bytes are read from the phone and thrown away.** It never opens, creates or stages a file anywhere, and it takes no `Path` argument. Keep the fastest, and store it in config `phone.parallel_reads_usb` plus a measured speed.

**Tests:**
- An end-to-end pull of the fake phone.
- A duplicate becomes an alias.
- The moved-file fast path makes no transfer.
- `FileChanged` goes back to `discovered`.
- Recovery sweeps `.part` files and resets `pulling`.
- reconcile drops the row of a missing file.
- Order is newest-first for camera.
- The reader test picks the fastest, using a fake with a per-reader throughput model.
- `test_reader_test_creates_no_files`: snapshot the backup folder, the staging folder and `SIFT_HOME` (excluding the DB, its WAL and SHM files, the config and the logs). After the reader test the snapshots are equal, and `open` was never called for writing under those trees (spied on `builtins.open` and `os.open` with write flags).
- `test_target_exists_same_hash_reuses_file`: a file is already at the target with the same bytes and no rows. The pull ends with one file, the rows inserted, no `_HASH8` sibling, and the `.part` gone.
- `test_target_exists_different_hash_gets_hash8`: the existing file is unchanged and the new file goes to the `_HASH8` path.
- `test_crash_between_rename_and_rows_recovers_without_duplicate`.
