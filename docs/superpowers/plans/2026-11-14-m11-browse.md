# M11: Browse and delete, Archive browser

Working method: `CLAUDE.md`. Roadmap: section 5, M11. Spec: 10B (browse and delete), 10A
(archive browser, empty folders), 12 (API), P8, P9. Deletes go through the M8 run machinery
(preflight, manifest, execute, quarantine) with source `browse`.

## Features, in build order

1. **Storage explorer** (`cleanup/browse.py`): one folder level of the phone's present files
   with sizes, counts and newest mtime rolled up per subfolder, and a backup status per file
   (backed up on Mac and SSD, Mac only, not backed up, changed since backup) and per folder
   (counts of each). Filters: name, kind, older than N days, at least N bytes, origin, status.
   Sort by name, size, date. `GET /api/browse?path=&sort=&...`.
2. **Smart lists** (spec 10B list, thresholds from `[browse]`): large videos, old downloads,
   installers, old screenshots, voice recordings, unchanged for a year, WhatsApp voice notes /
   audio / documents, temp and cache-like files, empty folders (from the last scan).
   `GET /api/browse/lists`, `GET /api/browse/lists/{key}` (paged files).
3. **Delete from Browse**: `POST /api/delete/preflight {source: "browse", ids, folders}`; a
   folder means every present file under it; files not backed up are skipped and listed in the
   response. Allowed anywhere under /sdcard except the never-delete list (floor + cleanup +
   browse extra). Typed count when any file is outside the default delete roots or more than
   200 files. Disposition chosen in the dialog (`disposition` on execute; default quarantine).
4. **Empty folders**: after a browse run, parent folders left empty on the phone are removed
   (`rmdir`, never recursive), except the standard top-level folders.
5. **Archive browser** (`cleanup/archive.py`): browse the backup tree on a mounted destination
   (folders, files, thumbnails by content), and restore selected files to the phone: free space
   for the selection + 2 GB, push to the original path with the original mtime (a clash gets
   `_restored`), media rescan. `GET /api/archive?dest=&path=`, `POST /api/archive/restore`.
6. **Web**: Browse page (folder tree, table or grid, details pane, bottom bar "N selected, X GB,
   Delete selected"), smart lists, "Choose files" from Analyse phone opens Browse filtered to
   the set's backed-up files, Archive page with restore; Quarantine links to it.

## Exit

P8 (P4 faults through the browse path) and P9 (manifest on disk before the first delete and
listing every planned path, whatever number of deletes happened before a crash) pass; deleting
from Browse works on the fake phone. Owner: 20 real files from Browse (with Gate C).

## Assumptions

- G1. Browse protection is the explicit-choice rule (F1, as for delete only): the protected
  label, document words and protected folders block; camera and screenshots do not.
- G2. "Changed since backup": a present file with a stored hash whose state is not `done`.
- G3. Empty-folder removal applies to browse runs only (Clean slate adds its own in M12), and
  never to a folder that still lists anything on the phone.
- G4. The archive browser shows the files Sift has replica rows for (not stray files), and
  restores only to the phone the content was backed up from.
- G5. Browse's never list is the built-in floor plus `browse.never_delete_extra`; Download and
  Documents (blocked on the suggestion tabs) may be deleted from Browse, as spec 10B says.
- G6. A folder tick means the files the owner saw: the same filters are applied on the server,
  and the UI turns folder ticks off while a filter or search is on.
- G7. Deferred to M9 polish (recorded, not built): the "Empty folders" smart list (needs a
  phone walk), "Back up now" on unbacked rows, the details pane, thumbnail grid, lightbox and
  folder tree, the GB total in the bottom bar, and thumbnails / Open in Finder on Archive.
