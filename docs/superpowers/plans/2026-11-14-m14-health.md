# M14: Health report and pre-reset checklist

Working method: `CLAUDE.md`. Roadmap: section 5, M14. Spec: 10D, 12 (health and checklist API),
settings `[health]`. Both helpers are read-only on the phone; the only phone writes are the
owner-started bug report capture (a file the phone writes for adb) and the restore helper's
contacts push after a reset (the existing archive `push_one`, never over a file).

## Features, in build order

1. **Probes and parsers** (`device/health.py`): a fixed `PROBES` dict (getprop, df, diskstats,
   meminfo, top one sample, battery, thermalservice, telephony.registry, wifi, contacts count)
   and parsers that return what they could read. Fixtures are synthetic and include Android 14,
   15 and 16 output shapes. Transport: read-only `health_probe(kind)`; FakeTransport returns
   canned output per Android version.
2. **Report and verdicts** (`health/report.py`): one pass collects every probe (each optional,
   "unavailable" on failure), then plain verdicts per area: security patch age, storage full
   (`storage_warn_pct`), top 5 apps by memory, battery health and temperature
   (`battery_temp_warn_c`), throttling, SIM and signal (with the "a reset may not fix this"
   advice when bad), 10 largest apps. Never a hardware diagnosis. Stored in `health_report`
   (migration `0012_health.sql`), exported as Markdown to `DEST_ROOT/.sift/reports/`.
3. **Bug report** (`health/bugreport.py`): `bugreportz -p` over adb, progress parsed, then the
   zip pulled to `DEST_ROOT/.sift/reports/` (temp name, linked into place). A task with Stop.
4. **Pre-reset checklist** (`health/checklist.py`): the 10 items of spec 10D. Automatic: (1) every
   backup set Confirmed and not stale; (2) WhatsApp local backup under 24 h (the M13 check);
   (3) a backed-up .vcf whose BEGIN:VCARD count matches the phone's contact count when known;
   (9) an app list saved. Ticks (with an optional date and note) in `reset_check`. Exports as
   Markdown.
5. **Restore helper**: push the newest backed-up .vcf to `/sdcard/Download/` for import, show the
   newest saved app list, link to Archive.
6. **API**: `POST /health/run` (task), `GET /health/report`, `POST /health/export`,
   `POST /health/bugreport` (task), `GET /reset-checklist`, `PUT /reset-checklist/{item}`,
   `POST /reset-checklist/export`, `GET /reset-checklist/restore`,
   `POST /reset-checklist/restore/contacts`.
7. **Web**: Health page in the sidebar (Run report, areas with verdicts, Capture bug report,
   Export), Pre-reset checklist page (items turn green, ticks, export, restore helper), Health
   card on Cleanup home.

## Exit

Parsers pass on the fixtures (Android 14 to 16), a missing probe leaves the rest of the report,
the checklist automatic items follow the database. Owner: run the report on the real phone and
compare with the phone's Settings screens.

## Assumptions

- K1. The report exports as Markdown only; PDF is the window's Print (deferred to M10).
- K2. The phone's contact count comes from `content query` on the contacts provider (read-only);
  when it fails, item 3 is green on a .vcf with at least one card.
- K3. A .vcf counts when Sift backed it up (a phone file ending in .vcf with a verified replica
  on the Mac folder); the newest one by phone mtime is used.
- K4. Bug report capture is a phone write the spec asks for (adb bugreport does the same); it
  is started only by the owner's click.
- K5. Health and bugreport run as TaskRunner tasks (`health`, `bugreport`), so they never overlap
  a backup or delete on the phone link.
- K6. (Owner request, amends M13.) Uninstalling or clearing WhatsApp also needs its newest chat
  backup file backed up, unchanged, on every required destination: Android removes the app's
  folder, chat backup included. A built-in "WhatsApp chat backups" set (Databases and Backups,
  current and legacy, not deletable) is on by default and joins an existing config once; a set
  that names those folders opts them in despite `include_whatsapp_db = false`. Older chat
  backups stay in the backup (a changed file gets a new name) until the owner deletes them.
- K7. (Owner request.) WhatsApp chat backups page: every saved chat backup in the backup folders
  by date, size and drive; the owner may delete older ones. Kept: the newest per app and folder,
  any whose file is still on the phone (it would be copied again). A delete needs every drive
  holding a copy plugged in and removes it everywhere, under the replication lock; it is the
  only owner-requested delete in a backup folder (I1 exception, like quarantine purge).

## Outcome

export, bug report capture, pre-reset checklist (4 automatic items, ticks, export), restore
helper (contacts push as a task, reinstall list), Health and Checklist pages. Owner requests:
WhatsApp uninstall needs its chat backup and media backed up; a built-in WhatsApp chat backups
set; a chat backups page to delete old copies. Review: 0 Critical, 7 Important (set re-added
after removal, config rewritten despite warnings, hard links failing on exFAT, guard trusting an
unplugged SSD and quarantined copies, dual-SIM false alarm, no backup guard on health routes,
WhatsApp media not covered) and the minor M1-M3, M5, M6, M8, M16 fixed. Carried (Minor, M9):
storage percentage vs Settings, contacts count scope, checklist reads the phone per request,
slow bug report stop, app list not tied to the phone, tick/date race, task progress lost on
leaving the page.
Final run: 1717 Python, 259 web, 13 e2e passed; lint clean. Owner: run the report on the real
phone and compare with Settings.
