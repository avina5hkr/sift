# M13: Apps tab

Working method: `CLAUDE.md`. Roadmap: section 5, M13. Spec: 10C, 12 (apps API), invariant I10,
P10. App actions change the phone (uninstall, clear data, trim caches); each needs a passed
apps check in the same request, and protected packages are refused on the server.

## Features, in build order

1. **Probes and parsers** (`device/apps.py`): `pm list packages -3 -i` (package, installer),
   `dumpsys diskstats` (app, data and cache sizes), `dumpsys usagestats` (last used), `dumpsys
   package` versions, `pm path` (APK paths). Every probe is optional: a failure is
   "unavailable", never an error. Parser fixtures are synthetic (no real package names from the
   owner's phone).
2. **Transport**: read-only `apps_probe(kind)` with fixed commands, `package_paths(pkg)`, and
   the writes `uninstall(pkg)`, `clear_data(pkg)`, `trim_caches()`; a package name must match
   the Android package grammar before any command is built. FakeTransport gets an app registry.
3. **Apps and protection** (`cleanup/apps.py`, migration `0011_apps.sql`): the app list with
   sizes, last used, installer, Play Store or not, Protected; suggestions (unused for 90+ days,
   by size, never pre-ticked). Protection (I10): `apps.protected_packages`. WhatsApp and
   WhatsApp Business unlock only when the local chat backup in their Databases folder is under
   24 hours old, the owner confirms the chat backup is complete, and types the app's name.
   Authenticators and owner-added packages unlock only through an explicit Unprotect.
4. **Actions**: `POST /api/apps/preflight {action, packages, unlock}` reports per package;
   `uninstall`, `clear-data` re-run the same checks, save the app list first (always, to every
   mounted destination, `.sift/apps/DATE.csv`), then act one package at a time.
   `trim-caches`, `export {apks}` (APKs of apps not from the Play Store, split APKs too, into
   `.sift/apps/apks/PACKAGE/`, never replacing a file), `unprotect {package, confirm}`.
5. **Web**: Apps page (table with name, package, size, data, cache, last used, installer,
   Protected badge; filters unused / large / not from Play Store; bottom bar Uninstall selected,
   Clear data, Clear all caches; the uninstall dialog with "Uninstalling deletes this app's data.
   This app cannot back it up.", offer to save APKs; WhatsApp unlock fields; Unprotect).

## Exit

P10 (uninstall and clear data on protected packages refused unless the unlock conditions
hold, through the API). Owner: a throwaway app uninstalled on the real phone.

## Assumptions

- J1. The app label is the package name for now (reading labels needs an APK parser; deferred).
- J2. WhatsApp's chat backup is `msgstore*.db.crypt*` in its Databases folder (current or
  legacy location); the newest one's mtime is what "under 24 hours old" checks.
- J3. The typed name is "WhatsApp" or "WhatsApp Business" (case-insensitive).
- J4. Unprotect lasts until the owner protects the app again (no timeout); it is recorded.
- J5. "Clear all caches" runs `pm trim-caches 999G` (asks Android to free as much as it can).
- J6. The built-in protected packages (WhatsApp, WhatsApp Business, the three authenticators)
  are always protected; `apps.protected_packages` only adds to them, compared case-insensitively.
- J7. An app action applies only to a package on a fresh `pm list packages -3` read in the same
  request; when that list cannot be read, nothing is done.
- J8. APKs are saved per version (`.sift/apps/apks/PACKAGE/VERSION/`), pulled to a temp name and
  linked into place when complete; a different file already there keeps its name.
