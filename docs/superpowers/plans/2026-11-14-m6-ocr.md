# M6: OCR, embeddings, clusters, Teach the app, search

Working method: `CLAUDE.md`. Roadmap: section 5, M6. Spec: 8 F–H, 11 (Teach the app), 12 (API).
Analysis reads the backed-up copies only; nothing touches the phone or a backup folder.

## Features, in build order

1. **OCR** (`analysis/ocr.py`, stage F): Apple Vision `VNRecognizeTextRequest`, accurate level,
   languages en-US and hi-IN after checking `supportedRecognitionLanguages` at run time. Stores
   `ocr_text` (NFKC, lowercase), `ocr_lang`, `text_density` (text box area / image area). Skips
   camera-EXIF images, images under 120 px on the short side, and unreadable ones.
2. **Model download** (`analysis/models.py`): the CLIP ViT-B/32 ONNX image and text towers (int8)
   and the tokenizer, from a pinned Hugging Face revision, each with a pinned SHA-256 and size.
   Downloaded only after the owner consents (the size is shown first) into
   `Application Support/models/<model>/`; a file whose hash differs is discarded.
3. **Embeddings** (`analysis/embed.py`, stage G): `EmbeddingModel` (encode_image, encode_text,
   dim, version); CLIP preprocessing (shortest side 224, centre crop, CLIP mean/std); 512-d,
   L2-normalised, stored as float16 in `content.embedding`; videos use their 50 % frame.
   CoreML execution provider when available, else CPU. Batches of 32.
4. **Clusters** (`analysis/cluster.py`, stage H): numpy cosine neighbours in chunks of 2,048;
   edges ≥ 0.88; union-find; clusters over 2,000 split again at 0.92; medoid = highest mean
   similarity; largest first; singletons dropped; near-duplicates count once in "N unique".
5. **API**: `GET /api/cleanup/models`, `POST /api/cleanup/models/download {consent}`,
   Analyze runs F, G, H when the model is present, `GET /api/cleanup/clusters`,
   `GET /api/cleanup/clusters/{id}`, `GET /api/cleanup/search?q=`, `POST /api/labels`
   (hashes or cluster id, label junk|keep, optional tag).
6. **Web**: model download card with size and consent; Teach the app (cluster cards: mosaic,
   member and unique counts, sample OCR text, Junk / Keep buttons, J and K keys); a search box.
7. **Fixtures**: greeting cards ("Good morning" over gradients and flowers, English and Hindi),
   document-like images with text, added to `scripts/make_fixtures.py`.

## Exit

Clusters browsable on the fake phone; with the real model, "good morning" returns the greeting
fixtures first; the Hindi OCR result recorded in `docs/spikes/m6-ocr.md`. Full suite, lint, web,
e2e green. One whole-branch review.

## Assumptions

- D1. Vision on this Mac lists hi-IN, so Tesseract is not bundled; if a Mac lacks hi-IN, OCR
  runs with en-US only and the app says Hindi text is not read (no extra binary).
- D2. Model: `Xenova/clip-vit-base-patch32` at revision `6b7c5237…`, the quantized (int8)
  towers; the multilingual text tower is left for later (Hindi search is not in the exit).
- D3. Tests use a small fake embedding model; tests with the real model run only when its files
  are present (marked slow), so the suite never downloads anything.
- D4. Embeddings are recomputed only when the model version changes; OCR only when the stage
  version changes.
- D5. Labels are stored per content (`label` table); labelling a cluster labels its members.
