# M12: Clean slate (Gate D)

Working method: `CLAUDE.md`. Roadmap: section 5, M12. Spec: 10A (keep list, flow, rules),
12 (slate API), invariants I3, I9, I11; P7, P8. Deletes go through the M8 run machinery with
source `slate`; nothing new deletes on its own.

## Features, in build order

1. **Keep rules and the plan** (`cleanup/slate.py`, migration `0010_slate.sql`): a plan stores
   its rules; every present file of the phone under /sdcard is decided, first match wins:
   never-delete list → `never`; Protected (protected label, document words, screenshots when
   `protect_screenshots`, protected folders) → `protected`; manual keep (files or folders the
   owner moved back) → `keep`; keep folders (default Documents) → `keep`; newer than N days
   (default 30) → `keep`; labelled keep (on) → `keep`; camera originals (off) → `keep`;
   path patterns (glob, empty) → `keep`; else `remove`. A `remove` file not backed up on every
   required destination is a gap (`not_backed_up`, or `no_set` when no backup set covers it).
2. **Tree and adjust**: removal and keep groups by folder (two levels under /sdcard) and by
   category (camera, screenshots, whatsapp, documents, junk, other) with sizes and sample ids;
   `POST keep {ids, folders}` moves items into Keep.
3. **Backup gaps**: `POST backup-gaps` starts a backup of the sets that cover the gap files;
   the plan cannot go on while gaps remain (files in no set must be kept or a set added).
4. **Disposition per category**: archive (default) or quarantine (suggested for junk); stored
   per planned file (`delete_item.quarantine`) so quarantine moves only those.
5. **Run**: `POST /slate/plan/{id}/preflight {dispositions}` refuses with gaps, creates a
   `slate` delete run of the removal set and starts the checks; the existing execute runs it
   (typed count always, `slate.typed_confirmation`), without the 5,000-file cap, progress in
   chunks of 500, empty folders removed (standard top-level folders stay). Resume: a stopped
   run is re-planned; files already gone are skipped.
6. **Web**: Clean slate wizard (rules → plan summary and tree → gaps with Back up now →
   adjust → disposition per category → the shared checks/confirm/progress/result).

## Exit

P7 (random trees and rules: no kept, protected or never-delete file is ever in a removal set
or deleted), P8 through the slate path, a 50k-file plan on the fake phone in seconds. Owner:
one small real folder by hand → Gate D.

## Assumptions

- H1. Protected for Clean slate is "documents, IDs, receipts, screenshots" (spec 10A table):
  the protected label, document words, screenshots, protected folders. Camera originals are
  kept only by the Origin rule (off by default), as the table says.
- H2. Manual keeps are stored per plan; a new plan starts without them.
- H3. A gap file outside every backup set cannot be backed up by Sift: it must be kept.
- H4. A picture whose words are not read yet (not indexed, or not OCR'd when it needs it) is
  kept as "Not analysed yet"; unreadable files and pictures close to a protected-labelled one
  are Protected too. Camera photos are not OCR'd (M6), so for them Clean slate relies on the
  protected label and similarity.
- H5. Keep folders and patterns are normalised (`/storage/emulated/0` → `/sdcard`, a relative
  pattern applies under /sdcard) or refused with 422, never dropped. A plain path keeps
  everything below it; `/**/` may stand for no folder.
- H6. The run is tied to the plan the owner reviewed (fingerprint of the removal set); a keep
  added after the checks blocks that run, and execute re-decides the plan and refuses if it now
  keeps any file. A slate run quarantines a content only when every one of its files chose
  quarantine.
